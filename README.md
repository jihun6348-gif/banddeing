# 반띵 — 1인가구 동네 소분 공동구매 (출시 버전 1.0)

방장이 공구방을 열고 → 이웃이 참여·입금하고 → 영수증 인증 후 공개 장소에서 픽업하고 → 후기를 남기는 서비스예요.
MVP를 실제 사용자에게 공개할 수 있게 보안·개인정보·운영 기능을 보강했어요.

## 1. MVP에서 바뀐 점

| 영역 | MVP | 출시 버전 |
| --- | --- | --- |
| 로그인 | 닉네임만 치면 그 계정으로 로그인 (남의 계정 접속 가능) | 이메일 + 비밀번호(암호화 저장), 카카오 로그인(키 설정 시) |
| 데모 | 데모 로그인 버튼·데이터 항상 켜짐 | `DEMO_MODE=1`일 때만 (로컬 시연용) |
| 시간 | 서버 시계 기준 (해외 서버면 9시간 어긋남) | 항상 한국 시간 |
| 픽업 장소 | ‘직접 입력’이 내 동네 인증 좌표(집)로 저장됨 | 지도에 핀을 꽂아 공개 장소 지정, 내 동네 5km 안 |
| 보안 | CSRF 방어 없음, 외부 주소로 리다이렉트 가능 | CSRF 토큰, 안전한 리다이렉트, 보안 헤더(nonce 기반 CSP), HTTPS 전용 쿠키, 요청 횟수 제한, 비밀번호 변경 시 다른 기기 로그아웃 |
| 운영자 | 운영자 이메일로 가입만 하면 운영자 | 운영자 이메일 인증(인증번호 또는 서버 명령)까지 해야 운영자 |
| 사진 | 파일 확장자만 검사, 촬영 위치(EXIF) 그대로 공개 | 실제 이미지인지 확인 후 위치정보를 지우고 다시 저장 |
| 동시 참여 | 두 명이 동시에 마지막 칸을 누르면 칸이 넘칠 수 있음 | DB 잠금으로 정확히 막음 |
| 학교 인증 | `.ac.kr`로 끝나면 바로 인증 | 메일로 6자리 인증번호 확인 (메일 설정 시) |
| 운영 | 신고가 쌓이기만 함 | 운영자 화면: 신고 처리, 공구방 취소, 이용 정지, 상점 등록 |
| 회원 | 탈퇴 불가, 약관 링크 없음 | 회원 탈퇴(개인정보 즉시 삭제), 이용약관·개인정보처리방침, 비밀번호 변경·재설정 |
| 기타 | 방장이 방을 닫을 수 없음 | 방장 공구방 닫기, 보관 기간 지난 기록 자동 삭제, 오류 화면, `/healthz` |

## 1-1. 웹프로그래밍 수업 내용 적용 (게시판 수정·삭제 · 예외 처리 · 로깅)

수업 자료(Django 게시판 CRUD, Exception, Logging)의 방식을 반띵(Flask)에 그대로 옮겼어요.

| 수업 내용 | 반띵에 적용한 곳 |
| --- | --- |
| **CRUD – U** `rhema_update` (기존 레코드를 폼에 채우고 POST로 덮어쓰기) | 공구방 수정 `/rooms/<id>/edit` (`room_update`) · 후기 수정 `/reviews/<id>/edit` (`review_update`) |
| **CRUD – D** `rhema_delete` (삭제는 POST로) | 공구방 삭제 `/rooms/<id>/delete` (참여자 없을 때만) · 후기 삭제 `/reviews/<id>/delete` |
| `write.html` 을 쓰기·수정에 같이 쓰기 | `review.html` 하나로 후기 쓰기·수정 (`record` 가 있으면 수정 모드) |
| `get_object_or_404` | `get_or_404()` — 없으면 `NotFound(404)` 예외 |
| **Exception** `try / except / else` + `error.html` (`err_msg`) | `room_delete`, `review_update`, `review_delete` — 남의 글이나 없는 글이면 404 안내 화면 + 오류 코드 표시 |
| **Logging** `LOGGING = { formatters, handlers, loggers }` | `app.py` 의 `logging.config.dictConfig` — Formatter `detail`, Handler `file`(logs/banddeing.log) + `console`, Logger `banddeing` |
| `logger.error(f'An error occurred : {e}')` | 404 예외는 ERROR, 403·400·429는 WARNING, 처리 못한 오류는 CRITICAL + 트레이스백 |

로그 예시 (`logs/banddeing.log`, 매일 자정 새 파일로 넘기고 90일치만 보관 — 개인정보처리방침의 ‘접속 기록 3개월 보관’과 맞춤):

```
[2026/11/22 16:14:41] INFO [banddeing:1153] 공구방 수정: room=2 host=3 changed=['상품명']
[2026/11/22 16:15:02] ERROR [banddeing:345] An error occurred : 404 Not Found: No Review matches the given query. (review_delete, user=2, path=/reviews/9/delete)
```

이메일·비밀번호 같은 개인정보는 로그에 남기지 않고 회원 번호만 적어요. 로그 수준은 `LOG_LEVEL` 환경 변수로 바꿀 수 있어요 (기본 INFO).

수정·삭제 규칙
- 공구방은 **모집 중**일 때만 고칠 수 있어요. 가격·수량·칸 수·픽업 장소·계좌는 참여자의 돈과 연결돼 있어서 고칠 수 없어요 (닫고 새로 열기).
- 참여자가 한 명이라도 있으면 **상품명·카테고리**도 고칠 수 없어요.
- 픽업 시간·마감 시간이 바뀌면 참여자에게 알림이 가요.
- 참여자가 한 명이라도 있으면 삭제 대신 ‘공구방 닫기’만 할 수 있어요.
- 후기는 남긴 뒤 7일 안에만 고치거나 지울 수 있어요 (신뢰도 조작 방지).

## 3. 인터넷에 배포하기 (Render 기준, 약 20분)

Render는 GitHub 저장소를 연결하면 자동으로 서버를 만들고 HTTPS 주소를 줘요.
지금 `render.yaml`은 **무료 플랜**이에요. 디스크가 없어서 재시작·재배포하면 DB·사진이 지워지고, 15분 동안 접속이 없으면 잠들어요 (시연용).
데이터를 유지하려면 **Starter 플랜(월 약 7달러) + 디스크 1GB(월 약 0.25달러)** 로 바꿔요 (`render.yaml` 주석 참고).

1. **GitHub에 올리기** — GitHub에서 새 저장소(Private 권장)를 만들고 이 폴더를 올려요.
   `.gitignore`가 DB·사진·비밀키를 빼 주니까 그대로 올리면 돼요.
2. **Render 가입** — https://render.com 에서 GitHub 계정으로 가입해요.
3. **Blueprint로 만들기** — Render 대시보드 › **New › Blueprint** › 저장소 선택.
   `render.yaml`을 읽어서 서버(싱가포르 지역), 디스크, `SECRET_KEY`를 자동으로 만들어요.
4. **환경 변수 입력** — 화면에 나오는 빈칸을 채워요 (`.env.example` 참고).
   - `OPERATOR_NAME` 운영 주체 이름 (예: 웹프로그래밍 8조 반띵팀)
   - `CONTACT_EMAIL` 문의 받을 이메일, `PRIVACY_OFFICER` 개인정보 보호책임자 이름
   - `ADMIN_EMAILS` 운영자로 쓸 이메일 — 이 이메일로 가입한 뒤 **이메일 인증까지** 해야 ‘마이 › 운영자 화면’이 보여요
     - 메일 설정이 있으면: 마이 › 운영자 이메일 인증 › 인증번호 받기 › 입력
     - 메일 설정이 없으면: Render 대시보드 › Shell 에서 `flask --app app verify-admin 운영자이메일`
     - `ADMIN_EMAILS` 에서 빼면 권한이 바로 사라져요
   - `PUBLIC_URL` **필수** — 배포 후 받은 주소(예: `https://banddeing.onrender.com`)를 넣고 다시 배포.
     비어 있으면 비밀번호 재설정 메일을 보내지 않아요 (가짜 주소로 링크가 만들어지는 것을 막기 위해)
5. **확인** — `https://내주소/healthz` 가 `{"ok": true}` 이면 끝. 운영자 이메일로 가입해서 화면을 둘러보세요.

다른 곳에 올릴 때는 `Dockerfile`을 쓰면 돼요 (Fly.io, Railway, 학교 서버 등). 데이터는 `/data` 볼륨에 저장돼요.

### 카카오 로그인 켜기 (선택)

1. https://developers.kakao.com › 내 애플리케이션 › 애플리케이션 추가
2. **앱 키 › REST API 키**를 `KAKAO_REST_API_KEY`에 넣어요.
3. **카카오 로그인 › 활성화 ON**, **Redirect URI**에 `https://내주소/auth/kakao/callback` 등록
4. **동의항목**에서 ‘닉네임’을 필수 동의로 설정
5. (보안 강화) 카카오 로그인 › 보안 › Client Secret 코드를 만들고 `KAKAO_CLIENT_SECRET`에 넣어요.

### 메일 켜기 (선택: 비밀번호 재설정 · 학교 인증 · 신고 알림)

Gmail 예시: 팀 Gmail 계정 › 보안 › 2단계 인증 켜기 › **앱 비밀번호** 만들기 →
`SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_USER=팀메일`, `SMTP_PASSWORD=앱비밀번호16자리`, `MAIL_FROM=반띵 <팀메일>`.
메일 설정이 없으면 비밀번호 찾기 화면은 문의 이메일을 안내하고, 학교 인증 칸은 숨겨져요.

## 4. 출시 전 체크리스트

- [ ] `SECRET_KEY`가 설정돼 있고 `DEMO_MODE`는 **꺼져 있다**
- [ ] `/terms`, `/privacy` 내용을 팀이 읽고 실제 운영 방식과 맞는지 확인했다 (운영자 이름·연락처·보호책임자 입력)
- [ ] 운영자 계정으로 가입해 운영자 화면이 보인다
- [ ] 휴대폰 두 대로 방 만들기 → 참여 → 입금 확인 → 영수증 → 수령 → 후기 한 바퀴를 돌려 봤다
- [ ] 추천 픽업 장소(운영자 화면 › 추천 픽업 장소 추가)를 우리 동네 기준으로 3~5곳 넣었다
- [ ] 법적 확인 (아래 5번)

### 이미 배포한 서버를 이번 버전으로 올릴 때

- 운영자도 이메일 인증을 **한 번 다시** 해야 해요 (위 4번 방법).
- 업데이트 직후 모든 사용자가 한 번 로그아웃돼요. 정상이에요 (비밀번호 변경 시 다른 기기 로그아웃 기능 때문).
- `PUBLIC_URL` 이 실제 주소로 들어가 있는지 확인하세요.

### 거래가 멈추지 않게 하는 자동 처리 규칙

| 상황 | 규칙 | 결과 |
| --- | --- | --- |
| 칸이 다 찼는데 입금 안 한 사람이 있음 | 모집 완료 후 24시간 | 미입금 자리 해제 → 다시 모집 (마감 지났으면 모집 실패) |
| 모두 입금했는데 방장이 구매 확정을 안 누름 | 마지막 입금 후 24시간 | **공구 자동 취소** · 참여자에게 환불 요청 알림 · 방장에게 환불 안내 |
| 픽업했는데 수령 확인을 안 누름 | 픽업 시간 후 48시간 | **자동 수령 처리 → 거래 완료** · 후기 요청 알림 |
| 위 경우에 처리 안 된 신고가 있음 | — | 자동 수령 처리를 하지 않고 운영팀 확인을 기다림 |

시간은 `app.py` 위쪽의 `DEPOSIT_HOURS`, `PURCHASE_HOURS`, `AUTO_RECEIVE_HOURS` 로 바꿀 수 있어요.
입금 확인 화면에는 구매 확정 기한이, 픽업 화면에는 자동 수령 시각이 보이고, 이용약관(제4조 거래 원칙)에도 같은 내용을 적었어요.

## 5. 법·운영상 꼭 확인할 것

이건 코드로 해결할 수 없는 부분이에요. 전문가(학교 창업지원센터, 법률 상담 등)에게 확인을 권해요.

- **위치기반서비스사업 신고**: 이용자 위치로 주변 정보를 제공하는 서비스를 사업으로 운영하려면
  ‘위치정보의 보호 및 이용 등에 관한 법률’에 따라 방송통신위원회에 위치기반서비스사업 신고가 필요할 수 있어요.
  수업 시연·소규모 테스트를 넘어 일반에 공개한다면 먼저 확인하세요.
- **개인정보처리방침**: 함께 넣은 방침은 이 코드가 실제로 하는 일(수집 항목, 공개 범위, 보관 기간, 국외 서버)에 맞춰 썼어요.
  운영 방식을 바꾸면 방침도 같이 고쳐야 해요.
- **식품 거래**: 개인 간 소분은 포장 식품 위주로 운영하고, 약관의 거래 금지 품목(주류, 직접 조리한 음식 등)을 지켜 주세요.
- **돈**: 반띵은 돈을 받지 않고 참여자가 방장에게 직접 송금해요. 에스크로(안전결제)를 넣으려면 PG사 계약이 필요해요.

## 6. 구조

| 파일 | 내용 |
| --- | --- |
| `app.py` | 서버 전체 (설정, 보안, 화면별 처리) |
| `db.py` | 테이블, 기존 DB 자동 업그레이드, 데모 데이터 |
| `templates/` | 화면 (Jinja) — `signup`, `consent`, `terms`, `privacy`, `admin`, `account_delete`, `room_edit` 등이 새로 생김 |
| `logs/` | 실행하면 생기는 로그 파일 (`banddeing.log`, git에는 안 올라감) |
| `static/` | 디자인, 아이콘, Leaflet 지도 |
| `tests/` | 자동 테스트 43개 (가입·보안·거래 전체 흐름·자동 처리 규칙·운영자 인증·XSS/CSP·카카오 로그인·수정/삭제·로깅) |
| `gunicorn.conf.py`, `Dockerfile`, `render.yaml` | 배포 설정 |
| `.env.example` | 환경 변수 목록 |
| `_backup_mvp/` | 수정 전 MVP 원본 |

공구방 상태: `모집 중 → 입금 대기 → 구매 진행 → 픽업 대기 → 거래 완료` (마감 미달 시 `모집 실패`, 운영자 취소 시 `운영 정책으로 취소`).
1칸 가격은 총 가격 ÷ 칸 수를 10원 단위로 올림해요. 자동 처리(마감, 입금 기한 24시간, 구매 미확정 24시간 자동 취소, 픽업 48시간 뒤 자동 수령, 픽업 30분 전 알림, 오래된 기록 삭제)는
별도 스케줄러 없이 요청이 들어올 때 최대 30초에 한 번 실행돼요.
